# Overview

This is an example of a bigger project - one that synthesizes multiple individual skills and allows you to demonstrate research skills such as:
-  reasonable mastery of a branch of bioinformatics (in this case, sequencing/omic analysis)
-  hypothesis-driven experimental design
-  organization (very important when you’re working on a big project with multiple datasets and dozens of scripts!).
-  synthesis and interpretation of results (technically optional for a code portfolio, but would be a **fantastic** idea to briefly include)

# Getting started with a project

This bioinformatics project looks at the microbiome differences between Parkinson’s disease and healthy controls. To make it a good portfolio project, the project should therefore include the most common microbiome analyses used in the field.

To get started:
1.  Find a public dataset ([kaggle](https://www.kaggle.com/), [qiita](https://qiita.ucsd.edu/), [in-built example data from the microbiome R package](https://microbiome.github.io/tutorials/Data.html), sample data provided in online coding tutorials (there are many), data downloaded from published papers, etc)
2.  Research the field: what are the most common analyses? (Ex. for microbiome: taxonomy bar plots, alpha/beta diversity, differential abundance)
3.  Make an analysis plan: what is your outcome (ex. Parkinson’s vs control)? What biological information will you learn from each analysis?
4.  Build your code according to your analysis plan**. Use the Methods sections from a few good-quality papers to guide you through - you won’t necessarily be familiar with all the key steps. For example, each type of 'omic data usually requires different normalization techniques.
5.  Go through your code again to 'clean' it - make it readable, well organized, add comments, remove unnecessary code, ensure your data are loaded/saved appropriately, etc.
6.  Optional but highly recommended: Add a quick results summary/interpretation. This could be put anywhere convenient (README, some other markdown file, etc). No need to be as detailed as a manuscript - just demonstrate that you understand the techniques you used and the results you obtained. Ideally, include pictures of your plots to help guide the reader.
7.  You can now highlight this project in your CV, cover letters, etc!

### ****Note:** DO NOT OVERCOMPLICATE IT, at least until you finish your analysis plan!!!! 

Avoid the overwhelming urge to fall into 'coding pits' - this is where you get something that almost looks like an exciting trend, and you endlessly run follow-up analyses to try and find out what’s driving the 'trend'. It’s a huge time-waster, usually fruitless, and more importantly, terrible science. Finish your analysis plan, and if you still think the trend is real, design a new test specifically to assess it. If you don’t see a clear signal, forget it and move on.
